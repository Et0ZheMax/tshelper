# Архитектура TSHelper

TSHelper — Windows desktop-приложение на Python 3.11+ с интерфейсом Tkinter/ttk. Главный цикл UI остаётся однопоточным, а сетевые проверки, интеграции и длительные операции выполняются в фоновых потоках или отдельных процессах.

## Основные блоки

- `src/tshelper/app.py` — композиция интерфейса, карточки пользователей, CallWatcher и координация интеграций.
- `src/tshelper/remote_ops.py` — SSH и Ubuntu automation через Paramiko/системные клиенты.
- `src/tshelper/windows_*` — Windows deployment через локальный subprocess, PsExec и PowerShell.
- `src/tshelper/browser_integration.py` — loopback HTTP-мост для браузерного расширения GLPI.
- `src/tshelper/updater.py` — получение метаданных GitHub Release, проверка и безопасная подготовка portable-обновления.
- `apps/adhelper2` — отдельное PySide6-приложение для операций Active Directory через PowerShell/RSAT.
- Print Monitor запускается отдельным процессом из закреплённой зависимости `prn-site-ping`.

## Данные и безопасность

Рабочие JSON-файлы и логи находятся в `%APPDATA%\TSHelper`. Пароли сохраняются через Keyring/Windows Credential Manager; резервный механизм использует DPAPI. Поставляемые каталоги ПО лежат в `config` и копируются в профиль пользователя перед редактированием.

Карточка пользователя хранит основной `pc_name` и список `pc_options`. Кэш ОС индексируется точным hostname, поэтому Windows- и Linux-машины с одним логином не конфликтуют. Контекстное меню передаёт в действие снимок выбранного хоста и не меняет основной ПК без подтверждения оператора.

Сетевые синхронизации AD/GLPI, ping-проверки и поиск номера CallWatcher выполняются вне Tk mainloop. Ping использует ограниченную очередь, а карточки, поисковый индекс и OS-бейджи обновляются инкрементально. Изменения настроек и кэша ОС группируются, чтобы не создавать серию синхронных записей на диск.

Встроенный ADHelper 2.1.0 расположен в `apps/adhelper2`. Он использует PySide6, отдельные сервисы AD/PowerShell и аудит операций; модуль управления доступами работает с группами и ACL, а OU-контроль сопоставляет организационные атрибуты с фактическим деревом каталога. Поля `department` и `section` связаны двусторонним справочником организационной структуры OMG; нестандартные существующие значения сохраняются до явного изменения оператором.

## Самообновление

На старте и затем каждые три часа TSHelper запрашивает последний GitHub Release. В течение одного сеанса одна версия предлагается только один раз. Для установки выбирается только архив со строгим именем `TSHelper-vX.Y.Z-portable.zip` и обязательным SHA-256 от GitHub. Клиент ограничивает размер загрузки, проверяет хеш, содержимое и версию архива, запрещает абсолютные пути, переходы `..`, ссылки и NTFS alternate data streams.

Самообновление поддерживает как корневой launcher portable-сборки, так и `scripts\run_tshelper.bat` в рабочей копии репозитория. После подтверждения внешний `scripts/apply_update.ps1` показывает собственное окно прогресса и дожидается завершения процесса приложения. Он заменяет только перечисленные каталоги и корневые файлы поставки, предварительно сохраняя их резервную копию в `%LOCALAPPDATA%\TSHelper\updates\backups`. Пользовательские данные в `%APPDATA%\TSHelper` и виртуальное окружение `.venv` не удаляются. При ошибке файлы откатываются, а результат фиксируется в `%APPDATA%\TSHelper\updater.log`.

## Версионирование

Версия задаётся только в `src/tshelper/version.py`. Git-тег и GitHub Release должны иметь вид `vX.Y.Z`. Клиент нормализует тег и показывает уведомление лишь тогда, когда версия релиза численно выше установленной.
