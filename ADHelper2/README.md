# ADHelper 2.0

Современное Windows-приложение для создания, поиска, изменения и увольнения пользователей Active Directory в доменах `pak-cspmz` и `omg.cspfmba`.

## Что изменилось

- Новый интерфейс на **PySide6 / Qt 6** с боковой навигацией, карточками, таблицами и тёмной/светлой темой.
- Долгие AD-операции выполняются в worker-потоках и не блокируют интерфейс.
- Python больше не формирует PowerShell-команды из пользовательских строк. Все операции находятся в фиксированных `.ps1`, данные передаются в UTF-8 JSON через `stdin`.
- Пароль не попадает в аргументы процесса PowerShell и хранится локально через Windows DPAPI.
- Создание сотрудника оформлено как мастер: заявка и распознанная карточка → AD-план → выполнение.
- Поиск и редактирование используют таблицу и карточку пользователя.
- Перед увольнением создаётся recovery-файл с исходными атрибутами и группами.
- Audit log записывается даже при частично выполненной или аварийно завершённой операции.
- Исправлен жёстко заданный `omg\\login`: NetBIOS-домен берётся из выбранного домена.
- `sAMAccountName` ограничивается 20 символами и проверяется во всех доменах.
- Manager назначается по однозначно найденному DN, а не по `Select-Object -First 1`.
- OU-кэш учитывает одновременно домен и SearchBase.
- Параметры доменов и список адресов офисов редактируются в разделе **Настройки** и сохраняются в `config_v2.json`.
- Для Windows PowerShell 5.1 все `.ps1` сохранены в UTF-8 BOM, чтобы кириллица не ломала синтаксический разбор.

### Разбор заявки при создании сотрудника

На первом шаге окно разделено на две части:

- слева вставляется исходный текст заявки из GLPI;
- справа сразу отображается распознанная и редактируемая карточка сотрудника.

ADHelper поддерживает как построчный формат, так и текст, скопированный одной строкой. Пункты формы распознаются по маркерам `1)`, `2)`, `3)` и названиям полей. Перед формированием плана оператор может исправить любое значение в карточке.


### Адрес офиса при создании

Поле **«Адрес офиса»** в мастере создания является редактируемым. Можно выбрать сохранённый адрес из списка или изменить его только для текущего пользователя. Разовое значение не добавляется в настройки автоматически.

В разделе **Настройки → Адреса офисов** можно добавлять, удалять и редактировать постоянные варианты. Для каждого адреса поддерживаются атрибуты `streetAddress`, `POBox`, `City`, `State`, `PostalCode` и `Country`. Новый список применяется сразу, без перезапуска ADHelper.

## Требования

- Windows 10/11.
- Python 3.11+ для запуска из исходников.
- PowerShell 5.1 или PowerShell 7.
- RSAT / модуль `ActiveDirectory`.
- Доступ текущей Windows-учётной записи к нужным доменам и OU.

## Первый запуск

1. Распакуйте проект на Windows-компьютере администратора.
2. Запустите `run_adhelper.bat`.
3. Откройте **Настройки**, проверьте параметры доменов, адреса офисов и задайте пароль новых пользователей.
4. Сохраните домены и запустите диагностику PowerShell, AD-модуля, контроллеров и OU.
5. Для приветственного документа скопируйте существующий шаблон в:
   `adhelper\templates\New User.odt`.

Плейсхолдеры шаблона:

- `{{LOGIN}}`
- `{{DOMAIN_LOGIN}}`
- `{{EMAIL}}`
- `{{PASSWORD}}`

## Сборка EXE

Запустите PowerShell от обычного пользователя:

```powershell
Set-ExecutionPolicy -Scope Process Bypass
.\build_exe.ps1
```

Результат появится в `dist\ADHelper2\ADHelper2.exe`.

## Локальные данные

Приложение создаёт каталог `%APPDATA%\ADHelper`:

- `config_v2.json` — настройки; пароль хранится только в DPAPI-токене;
- `audit\operations.jsonl` — полный журнал операций;
- `recovery\` — снимки перед увольнением;
- `generated\` — приветственные документы;
- `logs\adhelper.log` — диагностический лог.

## Важная проверка перед эксплуатацией

Сначала проверьте приложение на тестовом OU и тестовых пользователях. Для проверки создания используйте флаг **«Проверка без изменений»**. Для увольнения сначала нажмите **«Проверить план»** и убедитесь, что обе учётные записи найдены корректно.

### Контекстное меню пользователей

После поиска щёлкните по пользователю правой кнопкой мыши:

- **Копировать логин** — копирует `sAMAccountName`;
- **Печать приветственного листа** — доступна для учётной записи из любого домена, но доменный логин в документе всегда формируется через NetBIOS домена с профилем `omg` (например, `OMG\login`). Формирует ODT по шаблону `adhelper\templates\New User.odt` и подставляет пароль новых пользователей из настроек.

При редактировании карточки в AD отправляются только поля, изменённые оператором. Остальные отображаемые атрибуты повторно не записываются.

### Проверка тем интерфейса

Светлая и тёмная темы применяются ко всему приложению, включая отдельные диалоги, сообщения, контекстные меню, выпадающие списки и панель диагностики. После переключения темы перезапуск не требуется: уже открытые элементы интерфейса переполировываются и перерисовываются автоматически.

## Восстановление уволенной учётной записи

Вкладка **«Восстановление»** показывает recovery JSON из `%APPDATA%\ADHelper\recovery`, созданные до увольнения. После выбора файла сначала выполняется только проверка без записи в AD: GUID и логин должны совпасть, текущий объект должен находиться в OU уволенных (или уже в исходном OU после частичного восстановления), а исходный OU из JSON должен существовать.

После подтверждения ADHelper до первого изменения сохраняет `pre_restore_*.json` текущего состояния, затем восстанавливает сохранённые рабочие атрибуты, возвращает объект в исходный OU и последним шагом восстанавливает исходное состояние `Enabled`. Группы `memberOf` не меняются, потому что процедура увольнения ADHelper их не удаляет.

Для защиты от изменённых вручную JSON восстанавливается только пересечение сохранённых полей с текущим списком атрибутов, разрешённых процедурой увольнения. GUID из snapshot всегда сверяется с текущим объектом.
