# История изменений

Все заметные изменения проекта фиксируются в этом файле. Версии следуют Semantic Versioning.

## [Не выпущено]

## [5.15.4] — 2026-09-03

### Исправлено

- Обновление сохраняет правильную структуру каталогов без вложений вида `apps/apps`; повреждённое расположение ADHelper от предыдущей сборки восстанавливается автоматически перед запуском.
- Если среда ADHelper отсутствует после обновления, штатный bootstrap заново устанавливает зависимости и запускает приложение вместо сообщения о переустановке TSHelper.

## [5.15.3] — 2026-09-03

### Исправлено

- Ссылка YoPass из ADHelper содержит обязательный маршрут секрета `/s/`, поэтому ключ расшифрования подхватывается страницей автоматически.
- В HTML-ответе кратко выделено, что ссылка раскрывает данные только один раз; лишнее предупреждение оператору удалено.

## [5.15.2] — 2026-09-03

### Добавлено

- В ADHelper появился отдельный мастер создания учётных записей сотрудников контрагентов в PAK и OMG с разбором текста заявки и формированием карточки пользователя.
- Для контрагентов добавлена локальная OpenPGP-защита временных реквизитов и создание одноразовой ссылки YoPass сроком на семь дней; при недоступности сервиса HTML использует явно обозначенный резервный вариант.
- После создания учётных записей ADHelper открывает форматированный HTML-ответ для переноса в заявку GLPI.

### Исправлено

- GLPI Inventory больше не принимает случайное название Linux из меню, истории или другого блока основной карточки Computer за её операционную систему; текстовый поиск ОС выполняется только внутри соответствующей вкладки GLPI.
- Явный префикс hostname `W-`/`L-` защищает карточку от противоположной ошибочно распознанной ОС в ранее сохранённом результате GLPI.
- Старый кэш GLPI повторно нормализуется при загрузке, поэтому ошибочная запись `W-... = Linux` больше не переживает перезапуск приложения.
- Живой монитор явно отделяет найденный результат GLPI от применения hostname, а завершённая сверка сразу перерисовывает OS-бейдж затронутой карточки.
- Кнопки окна результатов сверки GLPI перенесены под таблицу и больше не обрезаются за правой границей на экранах небольшой ширины.
- Кнопка «Внести все ПК в карточки» теперь применяет все успешные результаты GLPI, включая пользователей с одним компьютером, а не только карточки с несколькими ПК.
- Окно получения IP показывает живой прогресс приоритетной сверки GLPI и сообщает итог: данные актуальны, карточка обновлена, найдены новые ПК либо возникла ошибка.
- При запросе IP приоритетная задача GLPI теперь гарантированно создаётся до запуска ping, поэтому окно не зависает на этапе подготовки из-за гонки фоновых потоков.
- Завершение GLPI напрямую уведомляет соответствующее окно IP после обновления карточки; удаление задачи из очереди больше не оставляет индикатор в состоянии подготовки.
- Живой статус окна IP обновляется через главный цикл Tk и показывает явную ошибку вместо бесконечного ожидания; время результатов GLPI отображается в UTC+3.
- Уведомление IP-окна о результате GLPI привязано к login пользователя, поэтому повторно используемый или быстро удалённый ID задачи не мешает завершить прогресс.
- Исправлен отсутствующий импорт нормализации login, из-за которого результат появлялся в мониторе, но не доходил до индикатора окна IP.
- Добавлена сквозная диагностика живой сверки IP/GLPI и журналирование необработанных ошибок Tk callback для воспроизведения проблем интерфейса по одному клику.
- Исправлен отсутствующий импорт `host_identity`, из-за которого IP-окно останавливалось сразу после создания и не регистрировало подписку на результат GLPI.
- Учётные записи контрагентов в PAK создаются в фактическом `OU=outsource` непосредственно под `OU=Users`.

- фирменный ярлык TSHelper в меню «Пуск», создаваемый штатным BAT-файлом и пригодный для закрепления на панели задач.

### Изменено

## [5.14.14] — 2026-09-02

### Добавлено

- в контекстное меню Linux-компьютеров добавлено подключение **Remote Linux** через системный RDP-клиент Windows по имени ПК или IP-адресу на порту `3390` с логином `support`;
- временный RDP-профиль безопасно формируется без пароля и автоматически удаляется после запуска подключения.

## [5.14.13] — 2026-08-31

### Исправлено

- обновлятор TSHelper сохраняет виртуальное окружение встроенного ADHelper и больше не переустанавливает его зависимости после каждого обновления; повторная установка выполняется только при изменении `requirements.txt` или повреждении окружения;
- правая карточка пользователя в ADHelper получила вертикальную прокрутку: блок контроля OU больше не ужимает поля редактирования;
- после сохранения атрибутов карточка и строка пользователя обновляются сразу из ответа Active Directory, без повторного поиска;
- модальное сообщение об успешном сохранении заменено заметным зелёным уведомлением сбоку, а ошибка сохранения показывается там же красным уведомлением.

## [5.14.12] — 2026-08-31

### Исправлено

- промежуточные стадии порционной перестройки больше не показываются пользователю: сетка обновляется как единая визуальная транзакция;
- во время фоновой раскладки вместо карточек со старыми координатами отображается нейтральный индикатор обновления списка;
- после изменения поискового запроса прокрутка согласованно возвращается к началу уже готовой выдачи;
- отложенный пересчёт scrollregion больше не может применить геометрию незавершённой сетки.

## [5.14.11] — 2026-08-31

### Добавлено

- постоянный ping-helper в отдельном процессе с собственной параллельной очередью проверок;
- неблокирующий обмен заданиями и результатами между Tk-интерфейсом и ping-helper через multiprocessing-очереди.

### Изменено

- ping не отключается и начинает подготовку через 40 мс после показа поисковой выдачи, при этом все системные вызовы выполняются вне процесса интерфейса;
- результаты завершившихся проверок возвращаются в UI порциями до 8 элементов и сохраняются в кэш даже после изменения поискового запроса;
- при закрытии TSHelper дочерний процесс и его очереди завершаются штатно.

## [5.14.10] — 2026-08-31

### Исправлено

- третий символ больше не включает статусы и ping-проверки непосредственно в обработчике поиска: сетевое обогащение запускается только после 260 мс без нового ввода;
- подготовка к ping-проверкам и применение кэшированных статусов выполняются порциями и отменяются при следующем нажатии клавиши;
- смена подписи и иконки статуса больше не пересоздаёт стили и OS-бейджи карточки;
- задержка фильтрации после ввода сокращена со 120 до 70 мс.

## [5.14.9] — 2026-08-28

### Исправлено

- показ, скрытие и обновление статуса карточек во время поиска выполняются небольшими порциями, не блокируя обработку клавиатуры;
- незавершённая отрисовка предыдущего запроса отменяется сразу после нового ввода, поэтому быстрый набор не создаёт очередь устаревших перестроений;
- очистка поиска отображает полный список постепенно и больше не вызывает микрофриз при возврате всех карточек.

## [5.14.8] — 2026-08-28

### Исправлено

- поиск больше не синхронизирует и не пересчитывает ОС всех карточек при каждом нажатии клавиши;
- результаты поиска используют заранее подготовленный индекс и обновляются только по изменившейся части сетки;
- задержка реакции поиска после ввода сокращена с 250 до 120 мс;
- карточки с большим числом компьютеров больше не растягивают строки: показываются основной ПК и количество остальных, при этом поиск и меню по-прежнему учитывают полный список.

### Изменено

- выделенный пункт временного переключения сокращён до **Действия с другим ПК**, чтобы контекстное меню не занимало лишнюю ширину.

## [5.14.7] — 2026-08-28

### Добавлено

- в полном отчёте GLPI Inventory появилась кнопка **Внести все ПК в карточки** для пользователей с несколькими активными компьютерами;
- при первом открытии многокомпьютерной карточки TSHelper просит один раз выбрать основной ПК и сохраняет выбор;
- внизу меню карточки добавлен визуально выделенный пункт временного переключения на другой ПК: выбранный там компьютер используется только для запускаемого действия.

### Изменено

- основное меню многокомпьютерной карточки сразу показывает действия сохранённого основного ПК; остальные ПК больше не смешиваются с ним в верхней части меню;
- импорт нескольких ПК заменяет старые догадки полным активным списком GLPI и по-прежнему исключает `lr-`/`wr-`.

## [5.14.6] — 2026-08-28

### Исправлено

- отчёт GLPI Inventory больше не показывает устаревший снимок текущих ПК и счётчика безопасных изменений во время работающего парсера;
- список однозначных замен повторно рассчитывается непосредственно перед применением.

### Улучшено

- отчёт автоматически обновляется каждые 1,5 секунды и явно отличает строки «Уже совпадает с GLPI» от готовых замен;
- кнопка переименована в **Применить однозначные** и блокируется, когда замен действительно нет.

## [5.14.5] — 2026-08-28

### Исправлено

- кнопка **AD Sync** отдельно проверяет OU `Уволенные` и автоматически удаляет карточки уволенных пользователей по AD-логину;
- для старых карточек без сохранённого AD-логина используется резервное точное сопоставление по полному ФИО.

## [5.14.4] — 2026-08-28

### Исправлено

- таймаут GLPI теперь действует до полного чтения HTML-тела, а не только до получения HTTP-заголовков;
- зависший обмен сообщениями с content script, service worker или служебной вкладкой больше не удерживает одну карточку бесконечно;
- общее время одной проверки ограничено 35 секундами, а срок возврата потерянного задания сокращён с 5 минут до 90 секунд.
- сбрасывающийся счётчик связи в живом мониторе подписан как `heartbeat`, отдельно отображается фактическое время текущей карточки.

## [5.14.3] — 2026-08-28

### Добавлено

- в живом мониторе GLPI Inventory появились кнопки **Пауза** и **Продолжить**;
- ручная пауза сохраняется вместе с очередью после перезапуска TSHelper, текущая карточка безопасно завершается, а новые задания не выдаются до продолжения.

## [5.14.2] — 2026-08-28

### Исправлено

- компьютеры удалённого доступа с префиксами `lr-` и `wr-` больше не отображаются в карточках TSHelper, не участвуют в ping и не предлагаются для удалённых действий;
- ранее сохранённые `lr-`/`wr-` также отфильтровываются из кэша GLPI и дополнительных ПК без необходимости вручную чистить пользовательские данные.

### Улучшено

- расширение сначала использует рабочий HTML-поиск GLPI, а не выполняет перед ним заведомо неподдерживаемый AJAX-поиск;
- точная проверка login нескольких User-кандидатов выполняется ограниченно параллельно;
- каждый HTML-запрос GLPI ограничен семью секундами, ожидание служебной вкладки сокращено с 12 до 8 секунд.

### Добавлено

- в меню **Инструменты** появилась ручная команда **Проверить обновления**; она использует штатный безопасный updater и сообщает как о новой, так и об актуальной версии.

## [5.14.1] — 2026-08-28

### Исправлено

- поиск GLPI User больше не зависит только от служебных параметров `/ajax/actors.php`: если они отсутствуют в конкретной конфигурации GLPI, расширение использует HTML-поиск User и затем обязательно подтверждает точный login в карточке;
- системная ошибка извлечения параметров Ticket больше не останавливает фактическую сверку всех пользователей.

### Добавлено

- живой монитор очереди GLPI Inventory с общим прогрессом, состоянием связи с расширением, текущим пользователем, стадией парсинга и последними результатами;
- повторный запуск ошибочных записей и приоритетная проверка выбранного пользователя из полного отчёта;
- расширение передаёт TSHelper промежуточные стадии поиска User, проверки login и чтения Computer.
- каталог `extensions` теперь обновляется вместе с portable-установкой TSHelper.

## [5.14.0] — 2026-08-28

### Добавлено

- отдельное расширение `TSHelper GLPI Inventory Bridge`, которое использует авторизованную браузерную сессию GLPI 11 и не требует API-токенов;
- персистентная очередь HTML-сверки: полный dry-run, проверка новых пользователей после AD Sync и при провале ping;
- кэш точных GLPI User/Computer ID, hostname и ОС, отчёт по неоднозначным случаям и резервная копия перед массовым применением;
- автоматическая замена ПК только при точном совпадении login и ровно одном активном Computer.

### Исправлено

- AD Sync больше не добавляет `w-login` вторым ПК к уже выбранному `l-login`, если `w-` является лишь стандартной догадкой AD;
- GLPI REST `initSession` теперь вызывается штатным методом GET вместо POST;
- определение ОС сначала использует данные конкретного Computer из GLPI, и только затем кэш ping и префикс hostname.

## [5.13.2] — 2026-08-26

### Исправлено

- автоматическая установка теперь работает не только через корневой `run_tshelper.bat` portable-сборки, но и при штатном запуске через `scripts\run_tshelper.bat` из репозитория;
- наличие `.git` больше не переводит обновление в режим простого открытия страницы релиза.

### Улучшено

- обновления проверяются при запуске и затем каждые три часа, поэтому постоянно работающий TSHelper увидит новый релиз без перезапуска;
- одна и та же версия предлагается не более одного раза за сеанс;
- окно загрузки показывает общий процент, объём, проверку целостности и прогресс распаковки;
- после закрытия TSHelper внешний установщик показывает отдельное окно с этапами резервного копирования, замены файлов, обновления компонентов и перезапуска.

## [5.13.1] — 2026-08-26

### Изменено

- выпущен проверочный patch-релиз для сквозной проверки автоматического обновления с TSHelper 5.13.0;
- функциональность приложения не изменялась.

## [5.13.0] — 2026-08-26

### Добавлено

- portable-версия TSHelper теперь предлагает установить новый GitHub Release прямо из приложения;
- обновление загружается в фоне с отображением прогресса, проверяется по размеру и SHA-256 из GitHub Release;
- архив проходит проверку структуры, версии и безопасных путей перед распаковкой;
- внешний установщик дожидается закрытия TSHelper, создаёт резервную копию, заменяет управляемые файлы, синхронизирует зависимости и перезапускает приложение;
- при ошибке установки выполняется откат к предыдущим файлам, а подробности сохраняются в `%APPDATA%\TSHelper\updater.log`.

### Совместимость

- автоустановка включается только в Windows portable-сборке; при запуске из Git checkout приложение предлагает открыть страницу релиза и не изменяет исходники.

## [5.12.0] — 2026-08-25

### Добавлено

- встроенный ADHelper обновлён до 2.1.0;
- `department (Управление)` и `section (Отдел)` в карточке пользователя стали связанными редактируемыми списками;
- выбор управления оставляет только относящиеся к нему отделы, лаборатории и отделения;
- выбор отдела в обратную сторону автоматически подставляет его единственное родительское управление;
- справочник обновлён по фактической выгрузке дерева из 56 OU и 43 используемых сочетаний атрибутов.

### Безопасность данных

- устаревшие значения, отсутствующие в актуальном справочнике, остаются видимыми и не перезаписываются без действия оператора;
- самостоятельный отдел очищает `section` только после явного выбора этого отдела.

## [5.11.1] — 2026-08-25

### Исправлено

- ADHelper 2.0.16 корректно извлекает структурированный JSON, даже если Windows PowerShell напечатал перед ним предупреждение об инициализации недоступного сетевого диска;

## [5.11.0] — 2026-08-21

- кэширование индекса групп, анализ ACL ресурса и проверка итогового членства пользователя;
- контроль соответствия OU атрибутам `division`, `department` и `section`;
- подтверждаемое перемещение пользователя в однозначно определённый правильный OU с записью в аудит;
- 13 новых тестов ADHelper; полный встроенный набор теперь содержит 80 тестов.

## [5.10.1] — 2026-08-21

### Улучшено

- AD Sync и GLPI Sync выполняются в фоне, показывают прогресс и больше не блокируют интерфейс;
- GLPI-запросы получили ограниченный тайм-аут, а AD-подключение не загружает ненужную схему каталога;
- карточки и OS-бейджи перерисовываются только при реальном изменении данных;
- поиск использует кэшированный текстовый индекс, сетка обновляет только изменившиеся позиции;
- ping-задачи дедуплицируются и не накапливаются сверх размера рабочего пула;
- сохранение окна настроек выполняет одну атомарную запись вместо десятков;
- кэш ОС сохраняется пакетно с задержкой;
- поиск неизвестного номера в AD вынесен из цикла CallWatcher и больше не задерживает обнаружение звонков.

## [5.10.0] — 2026-08-21

### Добавлено

- контекстное меню разделяет Windows- и Linux-действия по определённой ОС;
- настройка «Объединить функционал контекстного меню для Windows и Linux» возвращает полный набор действий для любого ПК;
- карточка показывает местоположение рядом с внутренним номером;
- поддерживаются несколько ПК и одновременно два OS-бейджа в одной карточке;
- при нескольких машинах действия запускаются через отдельное меню конкретного hostname.

### Исправлено

- `w-test` и `l-test` больше не используют одну запись кэша ОС;
- AD Sync не перетирает выбранный основной ПК, а сохраняет новый hostname дополнительным;
- GLPI Sync сохраняет телефон, местоположение и остальные поля карточки;
- обнаруженный альтернативный hostname сохраняется вместе с предыдущим, а не заменяет его безвозвратно.

## [5.9.2] — 2026-08-21

### Изменено

- исходники собраны в пакет `src/tshelper`, ресурсы, конфигурации и встроенные приложения разнесены по профильным каталогам;
- версия приложения вынесена в единый источник `src/tshelper/version.py`;
- проверка обновлений теперь уведомляет только о действительно более новой версии;
- пользовательские данные и логи перенесены в `%APPDATA%\TSHelper` с автоматической миграцией старых файлов;
- добавлены воспроизводимая релизная сборка, CI и краткая архитектурная документация;
- удалена устаревшая версия `TS HELP AD v3.8.py`.

### В составе

- ADHelper 2.0.13;
- Print Monitor 0.4.1;
- PowerShell Remote, SSH automation, GLPI bridge и CallWatcher.
