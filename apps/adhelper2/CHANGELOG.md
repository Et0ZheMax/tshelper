# 2.0.15

- Во вкладке **«Пользователи»** добавлен контроль соответствия фактического OU организационным атрибутам `division`, `department` и `section` для профиля OMG.
- Для выбранного пользователя ADHelper динамически читает дерево OU из AD, сопоставляет `department (Управление)` и `section (Отдел)` с реальными OU и показывает статус **«Совпадает / Несовпадение / Не определён»**.
- Добавлено безопасное нормализованное сопоставление русских форм слов: например, атрибут `отдел ресурсного сопровождения лабораторий` корректно сопоставляется с OU `отдел ресурсного сопровождения лаборатории`.
- При уверенном несовпадении появляется кнопка **«Переместить в правильный OU»**; перенос выполняется через существующий `Move-ADObject`, только после подтверждения и с записью в аудит.
- При неоднозначном сопоставлении автоматический перенос блокируется и предлагается ручной выбор из кандидатов.
- В таблицу поиска добавлена колонка **OU-контроль**, чтобы проблема была заметна прямо у выбранной строки.
- Подписи полей приведены к реальным AD-атрибутам с русской расшифровкой: `division (Подразделение)`, `department (Управление)`, `section (Отдел)` и др.
- Актуализировано дерево подразделений OMG для новых лабораторий и отделов, включая отдел ресурсного сопровождения лабораторий.

# 2.0.14

- Добавлена новая вкладка **«Доступы»** для поиска и безопасной выдачи групп доступа к файловым ресурсам.
- Текст заявки GLPI разбирается на сотрудника, путь, имя файла и требуемый тип доступа (RO/RW).
- Группы индексируются напрямую из настраиваемого `OU групп доступа`; индекс кэшируется локально в `%APPDATA%\ADHelper\access_groups_cache.json`.
- Умный рейтинг учитывает `Name`, `SamAccountName`, `Description`, `Info`, ключевые слова пути и суффиксы `_ro` / `_rw`.
- Если путь доступен с компьютера оператора, ADHelper читает ACL и резко повышает рейтинг групп, реально назначенных на ресурс.
- Добавление пользователя в группу выполняется только после явного подтверждения, с повторной проверкой пользователя, группы, SearchBase и итогового членства в AD.
- Повторное добавление не выполняется: интерфейс сообщает, что пользователь уже состоит в группе.
- Операция выдачи доступа записывается в общий аудит как `group_access`.
- В настройках домена добавлено поле **«OU групп доступа»**. Для `pak-cspmz` встроенное значение: `OU=Group,OU=csp,DC=pak-cspmz,DC=ru`.

# 2.0.13

- Добавлен протокол `adhelper://` для запуска создания сотрудника непосредственно из заявки GLPI.
- ADHelper принимает снимок полей заявки, автоматически открывает мастер «Создание» и заполняет карточку существующим парсером.
- После **успешного реального** создания пользователя (не dry-run) ADHelper открывает одноразовый callback GLPI для создания связанной заявки на выдачу оборудования.
- Обработчик `adhelper://` регистрируется в HKCU текущего пользователя Windows и не требует прав администратора.
- В контекстное меню результатов поиска добавлено действие «Удалить пользователя».
- Перед удалением отображается обязательное подтверждение с выбранным доменом; по умолчанию выбрана кнопка «Нет».
- Перед `Remove-ADUser` повторно проверяются домен, SearchBase, логин и GUID выбранной учётной записи.
- До удаления создаётся recovery JSON с полным снимком учётной записи; при ошибке чтения или записи снимка удаление блокируется.
- Удаление разрешено только при включённой AD Recycle Bin; вкладка «Восстановление» возвращает удалённый объект по GUID с исходными SID и паролем.
- Путь к recovery JSON показывается после удаления и сохраняется в журнал аудита ADHelper.

# 2.0.12

- Добавлена отдельная вкладка «Восстановление» для возврата учётных записей из OU уволенных по recovery JSON, созданным ADHelper до увольнения.
- Recovery JSON автоматически подхватываются из `%APPDATA%\\ADHelper\\recovery`; можно выбрать и внешний JSON вручную.
- Перед первым изменением выполняется безопасная проверка: совпадение GUID и логина, текущий OU, существование исходного OU, профиль домена и список допустимых атрибутов.
- Восстановление выполняется по этапам: атрибуты → исходный OU → исходное состояние Enabled. Следующие этапы блокируются, если восстановление атрибутов завершилось ошибкой.
- Восстанавливаются только атрибуты, которые ADHelper сам умеет очищать при увольнении и которые реально присутствуют в исходном snapshot. Произвольные имена атрибутов из редактируемого JSON игнорируются.
- Поддерживаются старые recovery JSON без поля `clear_attributes`: берётся безопасное пересечение сохранённых полей с текущей политикой увольнения.
- Перед восстановлением создаётся отдельный `pre_restore_*.json` текущего состояния уволенной учётки, чтобы само восстановление можно было откатить.
- Восстановление проверяет результат записи атрибутов, итоговый OU и состояние Enabled.
- Добавлен пошаговый прогресс без бесконечного индикатора и точные ошибки по каждому домену и этапу.
- Подтверждение восстановления использует тот же кликабельный логин для копирования в буфер обмена.
- Новая вкладка использует общую систему светлой/тёмной темы без локальных цветов.

# ADHelper 2.0.1

## Интерфейс

- Новый desktop UI на PySide6/Qt 6.
- Боковая навигация: обзор, создание, пользователи, увольнение, операции, настройки.
- Тёмная и светлая темы.
- Пошаговый мастер создания сотрудника.
- Табличный поиск и карточка редактирования.
- Ручной выбор Manager и OU при неоднозначном совпадении.
- Фоновые операции и индикаторы выполнения.

## Безопасность

- Все изменяемые данные передаются в PowerShell через JSON/stdin.
- Пароль не передаётся в `-Command` и не попадает в аргументы процесса.
- Пароль настроек защищён Windows DPAPI.
- Manager назначается по DN.
- Подтверждение точного логина перед увольнением.
- Защита от случайного дублирования сотрудника с одинаковым ФИО.

## Надёжность

- Разделены UI, модели, сервисы, хранилища и PowerShell-операции.
- Recovery-снимок до увольнения.
- Audit log через `finally`, включая частично выполненные операции.
- Пошаговые результаты очистки, отключения и перемещения.
- `sAMAccountName` ограничен 20 символами и проверяется в двух доменах.
- OU-кэш учитывает домен и SearchBase.
- Добавлена диагностика AD-модуля, контроллеров и базовых OU.
- Автоматическое чтение конфигурации и OU-map версии 1.x.

- Python compileall: успешно.
- 9 unit-тестов ядра: успешно.
- Создание всех шести экранов Qt в offscreen-режиме: успешно.
